# 双十一男护调研

在 Mac 上接到需求文字或截图即可开始，用户不用先找链接或填 Excel。只做资料调研，不领券、不下单。从本 SKILL.md 所在目录使用 `scripts/run`，批次建在用户当前工作区，不写入技能的安装目录。要检查安装就用 `scripts/run doctor`；只有明确要看演示时用 `scripts/run demo`，演示数据不能用于实际调研。

1. 在用户工作区选一个新的空批次目录，运行 `scripts/run flow --run "$RUN" start`，原需求是四款 × 抖音、天猫、淘宝、京东与七个竞品。若是先验证效果，用独立目录加 `--pilot`（控油洁面、欧莱雅、天猫和抖音）。继续时先看 `status`，同批次不重复选款、取相同素材。
2. 没有链接就用宿主的公开搜索/浏览器找品牌官网、旗舰店和平台商品详情。可用 `scripts/run evidence find '男士 控油洁面' --channels 天猫 抖音` 产生搜索入口，再实际打开或搜索；搜索入口本身不是候选。品牌不明时同时用冰川露、喷喷乳等有辨识度的简称定位可能品牌，保留不同款式；不要直接认定同系列。先回传少量候选图、完整品名、规格和出处，真正确认对象后再采优惠。
3. 用 `scripts/run capture page URL --out "$RUN/来源"` 读取公开页面，返回真实标题、正文路径、状态和候选原图。对商品图用 `scripts/run capture image IMAGE_URL --out "$RUN/素材" --from-page PAGE_RECEIPT` 或读取宿主可见的商品图。URL 取自真实页面。网页无法自动读取时，如平台允许，使用宿主浏览器；需要登录由用户本人完成。若宿主明确禁止访问则停止该入口，不换手段读取同一受限页面；可处理用户主动提供的商品截图作为独立证据。搜索摘要、短视频、官网价格不能替代渠道详情与结算证据。
4. 主动建候选 JSON，用 `scripts/run flow --run "$RUN" candidates FILE`。商品图保存在本次目录内，候选可看生成的“候选清单.html”。测试可 `select ID... --trial`；正式批次用 `--confirmed`，只根据用户明确选定的本品/已明确的品牌规格操作。没有明确规格的，继续找或标待补。竞品选同用途，规格/单位不可比较时分别展示。
5. 提取文字用 `scripts/run evidence read IMAGE --include-ocr`（macOS 本地 OCR）或宿主读图。把查看的原图、截图/规则正文与来源逐项关联，用 `observe FILE` 写回。平台规则、价格型/非价格型福利、日常/活动/宣传/结算实价要分开；没有同规格结算证据就不算叠券到手价。活动图要求原图印有本期标识；更新图还需有当前在用依据。缺项用 `gap '原因'` 记录。字段和样例见 [录入说明](references/workflow.md)，结构化契约见 [字段](references/fields.json)。
6. 运行 `scripts/run flow --run "$RUN" export`。交付候选清单、两套图片目录、带图 Word 和待补项。报告中的品牌认款参考图区与正式图片归档、渠道价分开。汇报本次真实取得的资料和未核验项；不要把试跑、历史样例、空目录称作业务验收。

需要验收天猫或抖音自动采集时，先按[四项逐页核对](references/workflow.md#四项逐页核对)做同款对照。每个平台都要有独立实页证据；公开详情抓不到就报明原因，不能用另一个平台、静态样本或人工抄录代替自动采到的数据。
